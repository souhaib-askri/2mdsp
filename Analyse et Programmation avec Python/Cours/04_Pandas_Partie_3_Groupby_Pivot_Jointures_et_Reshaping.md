> [!abstract] ملخص المحاضرة
> يغطي هذا الفصل أرقى العمليات التحليلية في مكتبة **Pandas**، مستهلاً بنموذج **التقسيم والتطبيق والدمج (Split-Apply-Combine)** وآليات التجميع `groupby`، مع تحليل الفرق الدقيق بين دوال التلخيص `.agg`، والبث المتوازن `.transform`، وتصفية المجموعات `.filter`، والتحليل الحرج لفخ التجميع المستقل وحلوله عبر `.idxmax()`. كما يوضح بناء **الجداول المحورية (Pivot Tables)**، وعمليات **دمج الجداول (Merging & Joins)**، وفنون **إعادة تشكيل البيانات (Reshaping)** بين التنسيقين العريض والطويل باستخدام `melt` و `pivot` مع تفكيك الفوارق الجوهرية لمعالجة التكرارات.

## 1. نموذج التقسيم والتطبيق والدمج (The Split-Apply-Combine Paradigm)

تعتبر عملية التجميع في Pandas تجسيداً لنموذج **Split-Apply-Combine**:

1. **التقسيم (Split)**: يتم تجزئة إطار البيانات الأصلي إلى عدة أطر بيانات فرعية مصغرة (**Sub-DataFrames / sf**) بناءً على قيم مفتاح التجميع.
2. **التطبيق (Apply)**: تُنفذ دالة حسابية مستقلة على كل إطار فرعي على حدة.
3. **الدمج (Combine)**: تُعاد لملمة النتائج المستخلصة من كافة المجموعات في إطار بيانات أو سلسلة موحدة جديدة.

```python
# التجميع وفق سنة الانتخابات وحساب المتوسط
elections.groupby("Year").mean()
```

> [!warning] كائن التجميع ليس إطار بيانات!
> ناتج استدعاء `elections.groupby("Year")` هو كائن خاص من نوع `DataFrameGroupBy`. هذا الكائن لا يطبع جدولاً، بل يمثل بنية مجزأة جاهزة لاستقبال إحدى عمليات المرحلة الثانية (Apply).

## 3. دوال التطبيق على المجموعات: `.agg` و `.size` و `.count`

### أ. التلخيص باستخدام `.agg()`
تسمح الدالة `.agg()` بتمرير دوال بايثون القياسية أو دوال NumPy أو تعبيرات lambda المخصصة:

```python
# حساب مؤشر النسبة إلى الذروة (Ratio to Peak - RTP) للأسماء
def ratio_to_peak(series):
    return series.iloc[-1] / max(series)

# نحدد صراحة العمود الرقمي لتفادي محاولة قسمة النصوص
rtp_table = f_babynames.groupby("Name")[["Count"]].agg(ratio_to_peak)
```

> [!danger] فخ الخطأ النوعي `TypeError`
> إذا استدعيت `f_babynames.groupby("Name").agg(ratio_to_peak)` دون حصر العمود `[["Count"]]`، ستحاول الدالة تطبيق معادلة القسمة على أعمدة نصية مثل اسم الولاية `"CA"`، مما يثير استثناء `TypeError`. لذلك يجب دائماً تحديد الأعمدة الرقمية المستهدفة!

### ب. الفرق الحاسم بين `.size()` و `.count()`
كثيراً ما يخلط المطورون بين التابعين:
* **`.size()`**: يعيد سلسلة تمثل **إجمالي عدد الأسطر** داخل كل مجموعة، شاملاً القيم الفارغة والمفقودة (`NaN`).
* **`.count()`**: يعيد إطار بيانات يحسب **عدد القيم غير المفقودة فقط (Non-Null values)** لكل عمود داخل كل مجموعة.

## 4. تصفية المجموعات `groupby().filter()` وفخ القيمة العظمى

### أ. التصفية على مستوى المجموعات بالكامل
تُستخدم دالة `.filter(func)` عندما نريد غربلة البيانات ليس سطراً بسطر، بل باستبعاد مجموعات بأكملها لا تحقق معياراً كلياً:

```python
# تصفية السنوات الانتخابية التي لم يتجاوز فيها الفائز الأكبر نسبة 45%
elections.groupby("Year").filter(lambda sf: sf["%"].max() < 45)
```

### ب. فخ القيمة العظمى المستقلة (The Woodrow Wilson Trap)
أراد المحللون معرفة أفضل نتيجة حققها كل حزب سياسي في تاريخه الأمريكي، فقام أحدهم بتنفيذ:
```python
elections.groupby("Party").max().head(10)
```
فأظهرت النتائج أن المرشح **Woodrow Wilson** فاز برئاسة عام **2020** بنسبة تصويت كاسحة!

> [!question] لماذا أنتج هذا الاستعلام نتيجة وهمية وخاطئة تاريخياً؟
> لأن دالة `.max()` طُبقت على **كل عمود في الجدول بشكل منفصل تماماً ومستقل عن باقي الأعمدة**:
> 1. في عمود السنة `Year`: التقطت أعلى سنة للظهور (2020).
> 2. في عمود المرشح `Candidate`: التقطت الاسم الأكبر في الترتيب الأبجدي ("Woodrow Wilson").
> 3. في عمود النسبة `%`: التقطت أعلى نسبة مئوية حققها الحزب في أي سنة في التاريخ.
> والنتيجة كانت سطراً مدمجاً مشوهاً يجمع قيماً من انتخابات وسنوات مختلفة تماماً!

### ج. الحلول الهندسية المعتمدة لاستخراج السطر الكامل للفائز
للحصول على السطر الواقعي الكامل الذي حقق أعلى نسبة دون تفكيك الأعمدة:

1. **الحل الاحترافي الأسرع عبر `.idxmax()`**:
   ```python
   # 1. استخراج الفهارس الفعلية للأسطر التي تحتوي على أعلى نسبة لكل حزب
   best_indices = elections.groupby("Party")["%"].idxmax()
   # 2. استخراج الأسطر الكاملة المقابلة لتلك الفهارس
   best_per_party = elections.loc[best_indices]
   ```
2. **الحل عبر الترتيب التنازلي وإزالة التكرار**:
   ```python
   best_per_party = (
       elections.sort_values("%", ascending=False)
       .drop_duplicates(subset=["Party"], keep="first")
   )
   ```

## 5. البث التناظري `transform()` والمنطق المخصص `apply()`

### أ. دالة `groupby().transform()`
تُستخدم عندما نريد حساب إحصائية جماعية (مثل متوسط راتب القسم) وبث النتيجة لكل موظف مع **الحفاظ التام على عدد أسطر الجدول الأصلي**:

```python
# إضافة عمود يحمل متوسط رواتب القسم لكل موظف
df["dept_mean_salary"] = df.groupby("department")["salary"].transform("mean")
```

### ب. دالة `groupby().apply()`
تطبق دالة مخصصة تستقبل كل إطار فرعي ككتلة واحدة وتستخلص منها مؤشراً حسابياً معقداً (مثل مدى الرواتب بين الأعلى والأدنى):

```python
def salary_range(group):
    return group["salary"].max() - group["salary"].min()

dept_dispersion = df.groupby("department").apply(salary_range)
```

## 6. الجداول المحورية (Pivot Tables)

توفر **الجداول المحورية (`pivot_table`)** أسلوباً رفيعاً لتلخيص العلاقات متعددة الأبعاد وتحويلها إلى لوحة متقاطعة الأسطر والأعمدة:

```python
babynames_pivot = babynames.pivot_table(
    index="Year",        # التسميات التي ستتحول إلى أسطر الجدول
    columns="Sex",       # الفئات التي ستتوزع كأعمدة مستقلة
    values=["Count"],    # العمود الرقمي الخاضع للعملية الحسابية
    aggfunc=np.sum       # دالة التجميع الرياضية
)
```

المقارنة مع GroupBy المتعدد:
* `df.groupby(["Year", "Sex"])[["Count"]].sum()` يعيد فهرساً متداخلاً (**MultiIndex**) رأسياً.
* `df.pivot_table(...)` ينشر المتغير الثاني أفقياً، مما يجعل قراءة الاتجاهات عبر الزمن أسهل وأكثر ملاءمة للمخططات البيانية.

## 7. دمج الجداول (DataFrame Merging & Joins)

عند دمج مصادر بيانات مختلفة (مثل دراسة شعبية أسماء الرؤساء الأمريكيين في قاعدة بيانات مواليد عام 2022):

```python
# 1. تصفية أسماء المواليد لعام 2022 فقط
babynames_2022 = babynames[babynames["Year"] == 2022]

# 2. استخراج الاسم الأول للمرشحين الرئاسيين ليكون مفتاحاً مشتركاً
elections["First Name"] = elections["Candidate"].str.split().str[0]

# 3. الربط والدمج عبر المفاتيح المشتركة
merged_df = pd.merge(
    left=elections,
    right=babynames_2022,
    left_on="First Name",
    right_on="Name"
)

# أو بصيغة التابع المباشر:
merged_df = elections.merge(babynames_2022, left_on="First Name", right_on="Name")
```

## 8. فنون إعادة تشكيل البيانات: التنسيق العريض والتنسيق الطويل (Reshaping: Melt & Pivot)

يمثل التحويل بين **التنسيق العريض (Wide Format)** و **التنسيق الطويل (Long / Tidy Format)** إحدى ركائز هندسة البيانات:

* **التنسيق العريض (Wide)**: تظهر فيه المتغيرات الزمنية أو الفئات كرؤوس أعمدة منفصلة (مألوف في جداول Excel).
* **التنسيق الطويل (Long / Tidy)**: يمثل كل صف رصداً وحيداً مستقلاً (المعيار الذهبي لمكتبات الرسوم المتقدمة مثل Seaborn ونماذج التعلم الآلي).

### أ. التحويل من العريض إلى الطويل: `pd.melt()`
```python
df_wide = pd.DataFrame({
    'Product': ['A', 'B', 'C'],
    '2022': [100, 150, 200],
    '2023': [120, 170, 210]
})

df_long = df_wide.melt(
    id_vars='Product',      # الأعمدة الثابتة كمعرفات
    var_name='Year',        # اسم العمود الجديد للرؤوس السابقة
    value_name='Sales'      # اسم العمود الجديد للقيم
)
```

### ب. التحويل من الطويل إلى العريض: `df.pivot()` مقابل `df.pivot_table()`
```python
# العودة للتنسيق العريض
df_back = df_long.pivot(
    index='Product',
    columns='Year',
    values='Sales'
)
```

> [!danger] الفارق الجوهري الحاسم: `pivot` مقابل `pivot_table`
> * **دالة `pivot()`**: تشترط صراحة أن تكون كل ثنائية `(index, columns)` **فريدة تماماً دون أي تكرار**. وإذا وُجد سجلان لنفس المنتج في نفس العام، ستنهار العملية وتولد خطأ:
>   `ValueError: Index contains duplicate entries, cannot reshape`
> * **دالة `pivot_table()`**: مصممة خصيصاً للتعامل مع التكرارات؛ فعندما تلتقي بسجلات متعددة لنفس الخلية، تقوم بدمجها باستخدام دالة التجميع `aggfunc="sum"` أو `mean` دون أي انهيار.
