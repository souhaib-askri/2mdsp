## 1. الخصائص المعمارية ونموذج التنفيذ (Architecture & Execution Model)

تتميز بايثون بأنها لغة عالية المستوى (**High-Level Language**)، متعددة النماذج البرمجية (**Multi-Paradigm**)، وتعتمد نظام التحديد الديناميكي للأنواع (**Dynamically Typed**).

### أ. اللغة المفسرة مقابل المجمعة (Interpreted vs Compiled)
في اللغات المجمعة سلفاً مثل **C** و **C++**:
* يمر الكود المصدري بمرحلة ترجمة مسبقة (**Ahead-of-Time Compilation - AOT**) عبر مصرف مثل `gcc`.
* ينتج عن الترجمة ملف تنفيذي ثنائي (**Machine Binary**) يتخاطب مباشرة مع وحدة المعالجة المركزية (**CPU**).
* يتميز التنفيذ بأقصى سرعة ممكنة وبغياب أي عبء للتحقق من الأنواع أثناء التشغيل.

أما في بايثون (بواسطة المفسر القياسي **CPython**):
1. **الترجمة إلى بايت كود (Bytecode Compilation)**: يُترجم الملف المصدري `.py` فورياً وبشكل غير مرئي إلى تعليمات وسيطة محايدة عن المنصة تُعرف بـ **البايت كود** (وتُحفظ في مجلد `__pycache__` بصيغة `.pyc`).
2. **التنفيذ عبر الآلة الافتراضية (Python Virtual Machine - PVM)**: تقوم الآلة الافتراضية بقراءة تعليمات البايت كود سطراً بسطر وتنفيذها.

```
C/C++  : [Source Code] ──(gcc/clang)──> [Native Binary] ──> [CPU Direct Execution] (Fastest)
Python : [Source .py]  ──(CPython)───> [Bytecode .pyc] ──> [PVM Loop + Type Check] ──> [CPU]
```

### ب. مقارنة الأداء وكيف يتغلب علم البيانات على بطء بايثون؟
* **ترتيب السرعة التجريدي**:
  $$\text{C} \approx \text{C++} > \text{Java} \gg \text{Python}$$
* **أسباب بطء بايثون النظري**:
  1. التحقق الديناميكي من أنواع المتغيرات عند كل عملية حسابية في وقت التشغيل (**Runtime Type Checking**).
  2. تغليف كل قيمة داخل كائن عام في الذاكرة (**PyObject Overhead**) يحمل عداد مراجع ونوع البيانات.
  3. حلقة التفسير السطرية داخل الـ PVM.
* **الحل الهندسي في بيئات علم البيانات**:
  تعتمد مكتبات تحليل البيانات الضخمة (مثل **NumPy** و **Pandas** و **SciPy** و **PyTorch**) على ملحقات مكتوبة بلغات **C** و **C++** و **Fortran**. تقوم بايثون بدور "لغة الغراء" (**Glue Language**) العالية التنظيم، بينما تُفوّض العمليات الحسابية والرياضية الثقيلة مباشرة إلى مصفوفات C المتراصة المتصلة في الذاكرة والمستفيدة من تسريع المعالجات التفرعية (**SIMD Vectorization**).

## 3. الوسائط وفك الحزم المتقدم (Functions & Argument Unpacking)

تدعم بايثون مرونة عالية جداً في تمرير المعاملات إلى الدوال:

### أ. أنواع المعاملات
1. **الوسائط الموضعية (Positional Arguments)**: تُمرر بالترتيب.
2. **الوسائط المسماة (Keyword Arguments)**: تُمرر بتحديد اسم المعامل `key=value` ويمكن تغيير ترتيبها.
3. **القيم الافتراضية (Default Parameters)**: تُحدد قيمة احتياطية في حال لم يمررها المستدعي.
   > [!warning] قاعدة الترتيب الإلزامية
   > يجب دائماً كتابة المعاملات التي لا تملك قيماً افتراضية قبل المعاملات ذات القيم الافتراضية في توقيع الدالة:
   > ```python
   > def func(a, b, c=0): ...  # صحيح
   > # def func(a=0, b): ...   # SyntaxError: non-default argument follows default argument
   > ```

### ب. وسائط التجميع المتغيرة: `*args` و `**kwargs`
* `*args`: تجمع أي عدد فائض من الوسائط الموضعية في بنية **Tuple** غير قابلة للتعديل.
* `**kwargs`: تجمع أي عدد فائض من الوسائط المفتاحية المسماة في بنية **Dictionary**.

```python
def demo(a, b, *args, **kwargs):
    print("a, b:", a, b)
    print("args:", args)
    print("kwargs:", kwargs)

demo(1, 2, 3, 4, x=10, y=20)
# المخرجات:
# a, b: 1 2
# args: (3, 4)
# kwargs: {'x': 10, 'y': 20}
```

### ج. فك الحزم المتقدم (Argument Unpacking) وحل سؤال الاختبار

> [!question] تمرين الاختبار: كم عدد الوسائط التي تستقبلها الدالة `f` في الاستدعاء التالي؟
> ```python
> a = [1, 2, 3]
> b = [4, 5]
> c = (6, 7, 8)
> d = (9, 10)
> f(*a, b, c, *d)
> ```

> [!example] التحليل والتفكيك الرياضي:
> 1. المعامل `*a`: العامل `*` يقوم بفك حزم القائمة `[1, 2, 3]`، فتنتج **3 وسائط منفصلة**: $1, 2, 3$.
> 2. المعامل `b`: تم تمريره كما هو ككائن قائمة واحد، فيمثل **وسيطاً واحداً**: `[4, 5]`.
> 3. المعامل `c`: تم تمريره ككائن صف (Tuple) واحد، فيمثل **وسيطاً واحداً**: `(6, 7, 8)`.
> 4. المعامل `*d`: يقوم بفك حزم الصف `(9, 10)`، فينتج **وسيطين منفصلين**: $9, 10$.
> 
> المجموع الكلي للوسائط الممررة = $3 + 1 + 1 + 2 = 7$ وسائط.

## 4. نطاقات المتغيرات وقاعدة LEGB وفخ `UnboundLocalError`

تحدد بايثون مدى رؤية المتغيرات وفق قاعدة هرمية دقيقة تُعرف باسم **قاعدة LEGB**:

1. **L - Local**: النطاق المحلي داخل جسم الدالة الحالية.
2. **E - Enclosing**: نطاق الدالة الخارجية الحاضنة في الدوال المتداخلة والإغلاقات (**Closures**).
3. **G - Global**: نطاق الملف أو الوحدة المصدري بالكامل (**Module level**).
4. **B - Built-in**: النطاق المدمج المسبق في نواة اللغة (مثل `len` و `sum` و `range`).

### الفخ الأكاديمي الشائع: `UnboundLocalError`
تأمل الكود التالي من شرائح المحاضرة:
```python
x = 42

def f():
    print(x)
    x = 7

f()
```

> [!danger] ماذا يحدث عند تنفيذ هذا الكود؟
> يفاجأ الكثيرون بأن هذا الكود لا يطبع `42`، بل ينهار مباشرة ويولد الخطأ:
> `UnboundLocalError: cannot access local variable 'x' where it is not associated with a value`
>
> **التفسير الدقيق**: عندما يفحص مفسر بايثون دالة `f()` أثناء مرحلة توليد البايت كود (قبل التشغيل الفعلي)، يكتشف وجود عملية إسناد `x = 7` داخل جسم الدالة. وبسبب هذا الإسناد، يصنّف المفسر المتغير `x` تلقائياً كمتغير **محلي (Local)** لكامل نطاق الدالة من أول سطر لآخر سطر. وعند تشغيل السطر الأول `print(x)`، يبحث المفسر عن القيمة المحلية لـ `x` فيجد أنها لم تُعطَ قيمة بعد في تلك اللحظة، فيتوقف فوراً!

### الحل باستخدام الكلمة المفتاحية `global`:
```python
x = 1

def f(a):
    global x
    x = x + 1
    return a + x

print(f(2) + f(4))
```
* في الاستدعاء الأول `f(2)`: تصبح $x = 1 + 1 = 2$، وتعيد الدالة $2 + 2 = 4$.
* في الاستدعاء الثاني `f(4)`: تصبح $x = 2 + 1 = 3$، وتعيد الدالة $4 + 3 = 7$.
* القيمة المطبوعة النهائية: $4 + 7 = 11$.

## 6. الدمج المتقدم وفك المصفوفات بواسطة `zip`

تعتبر الدالة المدمجة `zip(*iterables)` أداة محورية لدمج المتتاليات عنصراً بعنصر في هيئة مجموعات `tuples`:

```python
names = ['James', 'Tom', 'Mary']
grades = [100, 90, 95]
combined = list(zip(names, grades))
# [('James', 100), ('Tom', 90), ('Mary', 95)]
```

### فك دمج السجلات المتعددة (Unzipping):
```python
gradeBook = [['James', 100], ['Tom', 90], ['Mary', 95]]
unzipped_names, unzipped_grades = zip(*gradeBook)
# unzipped_names: ('James', 'Tom', 'Mary')
# unzipped_grades: (100, 90, 95)
```

> [!question] لغز الامتحان: ما هي نتيجة التعبير `list(zip(*zip(*L)))`؟
> المعطيات:
> ```python
> L = [[1, 2, 3], [4, 5], [6, 7, 8]]
> ```

> [!example] الحل خطوة بخطوة:
> 1. **الخطوة الأولى `zip(*L)`**:
>    نقوم بفك حزم القوائم الثلاث الداخلية: `zip([1, 2, 3], [4, 5], [6, 7, 8])`.
>    * تتوقف الدالة `zip` دائماً عند نهاية **أقصر متتالية**، وأقصر قائمة هنا هي `[4, 5]` ذات الطول 2.
>    * العنصر الأول من كل قائمة: $(1, 4, 6)$.
>    * العنصر الثاني من كل قائمة: $(2, 5, 7)$.
>    * النتيجة الوسيطة: زوج من الـ Tuples: `((1, 4, 6), (2, 5, 7))`.
> 2. **الخطوة الثانية `zip(*((1, 4, 6), (2, 5, 7)))`**:
>    نقوم بفك حزم هذا الناتج وتمريره لـ `zip` مرة أخرى: `zip((1, 4, 6), (2, 5, 7))`.
>    * العنصر الأول من كل زوج: $(1, 2)$.
>    * العنصر الثاني من كل زوج: $(4, 5)$.
>    * العنصر الثالث من كل زوج: $(6, 7)$.
> 3. **الناتج النهائي**:
>    $$[(1, 2), (4, 5), (6, 7)]$$

## 7. أركان البرمجة الدالية (Functional Programming: Map, Filter, Reduce)

ترتكز البرمجة الدالية في بايثون على معاملة الدوال ككائنات من الدرجة الأولى (**First-Class Citizens**) واستخدام تعبيرات لامدا (**Lambda Functions**) بدون اسم:

```python
square = lambda x: x ** 2
```

### أ. الدالة `map(func, iterable)`
تطبق الدالة المحددة على كل عنصر من عناصر المتتالية وترجع مولداً (**Generator**) يتميز بكفاءة استهلاك الذاكرة:
```python
celsius = [0, 10, 20, 30]
fahrenheit = list(map(lambda c: (c * 9/5) + 32, celsius))
# [32.0, 50.0, 68.0, 86.0]
```

### ب. الدالة `filter(predicate, iterable)`
تحتفظ بالعناصر التي تحقق الشرط المنطقي (تعيد `True`):
```python
numbers = [1, 2, 3, 4, 5, 6, 7, 8]
evens = list(filter(lambda x: x % 2 == 0, numbers))
# [2, 4, 6, 8]
```

### ج. الدالة `reduce(func, iterable)`
تستورد من مكتبة `functools`، وتقوم بعملية طي تراكمي (**Cumulative Reduction**) للمتتالية من اليسار إلى اليمين لتنتج قيمة وحيدة:

$$\text{reduce}(f, [x_1, x_2, x_3, x_4]) = f(f(f(x_1, x_2), x_3), x_4)$$

```python
from functools import reduce

# 1. إيجاد القيمة العظمى (Maximum)
max_val = reduce(lambda a, b: a if a > b else b, [12, 45, 2, 89, 34])
# 89

# 2. حساب مجموع الأعداد من 1 إلى 100
sum_100 = reduce(lambda a, b: a + b, range(1, 101))
# 5050

# 3. حساب القاسم المشترك الأكبر (GCD) باستخدام خوارزمية إقليدس
def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

gcd_result = reduce(gcd, [48, 64, 16])
# 16
```

## 9. المزخرفات والتغليف (Wrappers & Decorators)

المزخرف (**Decorator**) هو دالة تأخذ دالة أخرى كمدخل، وتوسع سلوكها دون تعديل كودها الأصلي، مستفيدة من مفهوم الإغلاقات (**Closures**).

### أ. المزخرف البسيط بدون معاملات
```python
def log_execution(func):
    def wrapper(*args, **kwargs):
        print(f"[LOG] جاري تنفيذ الدالة: {func.__name__}")
        result = func(*args, **kwargs)
        print(f"[LOG] اكتمل التنفيذ بنجاح.")
        return result
    return wrapper

@log_execution
def greet(name):
    print(f"مرحباً {name}!")

greet("Ali")
```

### ب. المزخرف المتقدم الذي يقبل معاملات (`Decorator with Arguments`)
عندما يحتاج المزخرف إلى وسائط (مثل عدد مرات التكرار `@repeat(3)`)، نحتاج إلى ثلاثة مستويات من الدوال المتداخلة:
1. الدالة الخارجية لاستقبال معاملات المزخرف.
2. الدالة المتوسطة لاستقبال الدالة المستهدفة.
3. الدالة الداخلية (`wrapper`) لاستقبال معاملات استدعاء الدالة وتنفيذ العمليات:

```python
def repeat(n):
    def decorator(func):
        def wrapper(*args, **kwargs):
            for i in range(n):
                func(*args, **kwargs)
        return wrapper
    return decorator

@repeat(3)
def ping(server):
    print(f"Pinging {server}...")

ping("8.8.8.8")
# سيتم طباعة الرسالة 3 مرات متتالية
```

## 10. البرمجة كائنية التوجه (OOP: Classes & Inheritance)

تدعم بايثون البرمجة كائنية التوجه بشكل أصيل:

```python
class Etudiant:
    def __init__(self, nom, prenom):
        self.nom = nom
        self.prenom = prenom
        self.notes = []

    def ajouter_note(self, note):
        self.notes.append(note)

    def moyenne(self):
        return sum(self.notes) / len(self.notes) if self.notes else 0.0

    def __str__(self):
        return f"{self.prenom} {self.nom} – Moyenne : {self.moyenne():.2f}"

class EtudiantMaster(Etudiant):
    def __init__(self, nom, prenom, stage):
        # استدعاء مشيد الفئة الأب
        super().__init__(nom, prenom)
        self.stage = stage

    def __str__(self):
        # توسيع دالة التمثيل النصي للفئة الأب
        return super().__str__() + f" – Stage : {self.stage}"

# تجربة الكائنات
em = EtudiantMaster("Ben Salah", "Yasmine", "InstaDeep")
em.ajouter_note(18.5)
em.ajouter_note(17.0)
print(em)
# Yasmine Ben Salah – Moyenne : 17.75 – Stage : InstaDeep
```

## 11. دورة حياة مشاريع علم البيانات (Data Science Lifecycle)

يمثل مسار عمل علم البيانات إطاراً متكرراً وتفاعلياً (**Iterative Lifecycle**) يتجاوز مجرد كتابة الأكواد:

```
[1. صياغة الإشكالية والتساؤل] 
          │
          ▼
[2. تجميع البيانات وتنظيفها وتجهيزها] ◄────────┐ (تغذية راجعة)
          │                                     │
          ▼                                     │
[3. التحليل الاستكشافي والتصور البياني EDA] ───┘ (اكتشاف شذوذ أو نواقص)
          │
          ▼
[4. بناء النماذج والتنبؤ والتعلم الآلي] ◄──────┐ (إعادة ضبط)
          │                                     │
          ▼                                     │
[5. اتخاذ القرارات وحلول الأعمال ورفع التقارير] ─┘
```

1. **صياغة التساؤل (Question Formulation)**: تحويل المشكلة الواقعية إلى أهداف تحليلية وفرضيات قابلة للقياس الرياضي.
2. **جمع وتنظيف البيانات (Data Acquisition & Cleaning)**: سحب البيانات من الملفات (CSV, JSON, SQL) ومعالجة القيم المفقودة وغير المتسقة.
3. **الاستكشاف المبدئي (EDA)**: حساب الإحصاءات الوصفية، ورسم التوزيعات لمعرفة خصائص المتغيرات وعلاقات الارتباط.
4. **النمذجة الرياضية (Modeling & Prediction)**: تطبيق خوارزميات التعلم الآلي والتحقق من الفرضيات.
5. **اتخاذ القرارات (Decisions & Solutions)**: صياغة التوصيات بناءً على النتائج ومشاركتها مع أصحاب المصلحة.
